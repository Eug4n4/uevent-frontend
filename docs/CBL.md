 Main principles of UI/UX?
It’s basically about making things intuitive and clean. You’re looking at stuff like consistency, clear visual hierarchy, and accessibility—making sure the user doesn't have to "think" to get from A to B. It’s a "user-first" mindset type thing.

 Questions for a great UI?
Ask yourself: "Who is actually using this?" "Is the most important action obvious?" and "Does this look cluttered?" You basically want to know if a total stranger could navigate it without a manual.

 What is REST concept?
REST (Representational State Transfer) is just an architectural style for web APIs. It uses standard HTTP methods like GET and POST and keeps things stateless, meaning each request has everything it needs to be processed without the server remembering the previous one.

What is a RESTful web service?
It’s just a service that actually follows those REST principles. It treats everything as a "resource" that you can access via a URL.

 SOAP vs. REST?
SOAP is a much stricter, older protocol that uses XML for everything. It’s very "official" and heavy. REST is more of a flexible style that usually uses JSON and is way easier to work with for modern web apps. 


 Why write documentation?
Because you will forget how your own code works in three months. It’s for your future self and your teammates so they can actually use the service without having to read every single line of source code.

 Why support JSON and XML?
It’s an interoperability type thing. While JSON is the king of the web now, plenty of legacy systems or specific enterprise tools still rely on XML. Supporting both makes your service way more flexible for different clients.

 What is a git-flow?
It’s a specific branching strategy for Git. You have a main branch for production, a develop branch for integration, and then separate branches for features, releases, and hotfixes. It keeps the repo from becoming a total disaster when multiple people are coding at once.


 What is an SQL injection & how to defend?
It’s when a hacker sneaks malicious SQL code into an input field (like a login box) to trick your database into giving up data. To stop it, you use "parameterized queries" or an ORM so the database treats the input as just plain text, not executable code.


 TypeScript vs. JavaScript?
TypeScript is basically JavaScript with "types." It lets you define what kind of data (strings, numbers, etc.) you’re working with, which helps catch bugs while you're still typing instead of when the app crashes in production.

 What is a type annotation?
It’s just you telling TypeScript what a variable is supposed to be. 
Example: `let age: number = 25;`—that `: number` part is the annotation.

 What does .tsx mean?
The `.tsx` extension is for TypeScript files that contain JSX (React code). It’s the typed version of a `.jsx` file. Use `.ts` for plain logic and `.tsx` for your components.

 Defining props in React?
You usually define an `interface` or a `type` that lists all the props and their types, then you pass that to your functional component definition so React knows exactly what data it's getting.

 Nest.JS vs. Express?
Express is very "minimalist"—it gives you the tools but no real structure. Nest.JS is a full framework built on top of Express (usually) that gives you a strict, organized architecture using classes and decorators. It's like the "grown-up" version for big projects.

 What is a DTO in Nest.JS?
A Data Transfer Object. It’s just a class that defines the "shape" of data being sent in a request. It’s used to validate that the user is actually sending the right stuff before it hits your database.

 Main building blocks of Nest.JS?
Modules (to group code), Controllers (to handle incoming requests), and Providers/Services (to handle all the heavy lifting and logic).


 What is Swagger?
It’s a set of tools that helps you design and document your APIs. It basically looks at your code and generates a manual for you.

 What is Swagger UI?
It’s the actual visual webpage generated by Swagger. It lets you see all your API endpoints and even "try them out" by sending real requests directly from the browser.

 What is TypeORM?
It’s an Object-Relational Mapper. It lets you interact with your database using TypeScript classes and methods instead of writing raw SQL strings. It makes managing your data feel way more like regular coding.
